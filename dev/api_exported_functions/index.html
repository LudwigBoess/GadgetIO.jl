GadgetIO.assemble_global_halos — Method
assemble_global_halos(metas, descendants, first_snap, last_snap)
    -> (halos::Vector{MergerTreeHalo}, links::LinkTable, first_in_snap::Dict{Int,Int32})

Build the global halo array from per-snapshot subfind meta and descendant files. Halos are concatenated in reverse-snapshot order (last_snap, last_snap-1, …) which matches the C code so that root halos come first.

metas[snap] is a SubfindMeta. descendants[snap] is a SubDesc (only required for snap < last_snap). The returned links::LinkTable holds the SoA pointer + Len fields used by set_progenitor_pointers! and walk_it!. first_in_snap[snap] returns the 0-based offset of the snapshot's first halo in the global array.

The MergerTreeHalo entries are written with NO_HALO placeholders in their FirstProgenitor/NextProgenitor slots; the final values are merged in by generate_trees when it emits per-tree halos.

GadgetIO.build_merger_forest — Method
build_merger_forest(treedir; forest_id=nothing, root_id=nothing,
                    ntrees_max=8, min_halos=1,
                    particle_mass=CT_DEFAULT_PARTICLE_MASS,
                    verbose=true) -> MergerForest

Read the trees of a single consistent-trees forest from a rockstar/ctrees trees/ directory (the one holding forests.list, locations.dat and the tree_*.dat files) and return them as a MergerForest.

Selecting the forest:

  • forest_id — read this specific ForestID; or
  • root_id — read the forest that contains this TreeRootID; or
  • neither — default: the forest with the largest total halo count (the main cluster's environment).

Only the ntrees_max largest trees in the forest (by halo count, a proxy for mass) with at least min_halos halos are read — a forest can contain tens of thousands of tiny trees, but a merger plot only needs the few massive ones. Pass ntrees_max = nothing to read all of them.

Trees are read by seeking directly to each one via locations.dat, so cost scales with the trees actually requested, not with the full file size.

Example

using GadgetIO, MakieHelper, CairoMakie
treedir = "A2256/cr_mhd2/rockstar/trees"
forest  = build_merger_forest(treedir; ntrees_max = 6)
amap    = scale_factor_map(joinpath(treedir, "tree_0_0_0.dat"))
plot_merger_forest(forest;
                   snap_to_scale = s -> amap[s],
                   mass_of       = h -> log10(h.M_TopHat))

GadgetIO.decide_upon_descendant! — Method
decide_upon_descendant!(descA_B, descA_C, descSnapA, weightA_B, weightA_C,
                        countB, countC; weight_fak=3.0)

Re-route subhalos in snap A from their primary descendant in B to the secondary one in C when one of the following holds:

  1. The B-descendant has multiple progenitors and the C-descendant has none — i.e. the halo seems to merge in B but survive in C.
  2. The C-route weight (skipping snap B) is more than weight_fak× the B-route weight (only if skip_by_weight=true).
  3. No B-descendant exists but a C-descendant does.

This is L-BaseTree's decide_upon_descendant ported with explicit arguments (no globals). Modifies the descendant arrays in place.

GadgetIO.determine_descendants — Method
determine_descendants(catA, catB; alpha=2/3, snapnum_B=-1)
    -> (descendant_haloindex, descendant_snapnum, descendant_weight)

For each subhalo in catA, find the subhalo in catB that maximises the rank-weighted ID-overlap score. Returns three vectors of length length(catA):

  • descendant_haloindex[i] — 0-based descendant index in catB, -1 if none
  • descendant_snapnum[i] — snapnum_B if found, -1 otherwise
  • descendant_weight[i] — score of the chosen descendant

Mirrors the C determine_descendants in L-BaseTree: collect per-halo candidate (haloB, weight) pairs, sort by haloB, sweep to aggregate weights per haloB, and pick the argmax. Uses per-task scratch buffers under Threads.@spawn-based parallelism so it is safe across Julia versions including the post-1.10 task-migration model.

GadgetIO.filter_subfind — Function
filter_subfind(sub_base::String, filter_function::Function, files=nothing)

Filters all entries in a subfind file that fulfill the 'filter_funcion' requirements and returns a Vector of HaloIDs.

Examples

# load packages
using GadgetIO, GadgetUnits

# define filter function
function find_mvir_gt_1e15(filename) 
    h = read_header(filename)
    GU = GadgetPhysical(h) # unit conversion

    # read Mvir and convert to solar masses 
    M = read_subfind(filename, "MVIR") .* GU.m_msun

    return findall(M .> 1.0e15)
end

# basename of subfind output (without .*)
sub_base = /path/to/groups_000/sub_000

# get relevant halos from first 10 files
halo_ids = filter_subfind(sub_base, find_mvir_gt_1e15, 0:9)

GadgetIO.find_main_halo — Method
find_main_halo(snap_base::String; b::Real=0.2, omega_b::Real=0.04,
               linking_length::Union{Real,Nothing}=nothing,
               center::Symbol=:potential, verbose::Bool=true)

Centre of the most massive halo in the high-resolution region of a zoom simulation, in code units. The halo is the most massive friends-of-friends group of the high-resolution dark matter (particle type 1).

Only the high-resolution dark matter is linked. Gas particles that left the high-resolution region, or particles next to massive low-resolution particles, can have a lower potential than the halo centre, so the global potential minimum is not a reliable centre.

Keyword Arguments

  • b: linking length in units of the mean particle separation of type 1 at the mean dark matter density of the box (see GadgetIO.fof_linking_length).
  • omega_b: baryon density parameter of the simulation, which is not stored in the header. Only used if the snapshot contains gas.
  • linking_length: linking length in code units, replaces the one from b.
  • center: definition of the centre
    • :potential: position of the group member with the lowest potential (needs the POT block)
    • :shrinking_sphere: shrinking-sphere centre of the group members (see GadgetIO.shrinking_sphere_center)
  • verbose: print the linking length and the properties of the group.

Positions are unwrapped around a high-resolution particle, so the centre is the periodic image next to the high-resolution region, also if the halo lies across the border of the box.

Examples

center = find_main_halo(snap_base)

# without a POT block in the snapshot
center = find_main_halo(snap_base, center=:shrinking_sphere)

GadgetIO.generate_trees — Method
generate_trees(halos, links, last_snap_nsub) -> MergerTreeFile

Walk each subhalo of the final snapshot that has not been visited yet and flatten its connected tree depth-first. Pointer fields are remapped from global halo indices to per-tree indices so the resulting MergerTreeFile is self-contained.

last_snap_nsub is the number of subhalos in the final (root) snapshot, i.e. length(metas[last_snap].sublen). These are the candidate roots — see L-HaloTrees generate_trees.

Single-pass: one DFS per tree records both aux.target_index and the per-tree origin (global indices in DFS order). The per-tree MergerTreeHalo output is constructed directly from halos + links with pointers remapped via aux.target_index — no intermediate verbatim-copy traversal.

GadgetIO.load_subhalo_catalogue — Method
load_subhalo_catalogue(sub_base) -> SubhaloCatalogue

Read SLEN, SOFF and PID from a subfind output. SLEN/SOFF and PID typically live on different subfind parttypes (subhalo-type vs ID-type in LGADGET3), so we issue one batched read per parttype.

For multi-file subfind outputs, different L-Gadget/SUBFIND flavours write SOFF differently:

  • NEW_SUBFIND (without LGADGET3) stores global SOFF already.
  • LGADGET3 (and the legacy non-NEW_SUBFIND path) store SOFF local to each sub-file's PID block and require an idcount bump — cat->SubOffset[subcount + i] = suboffset_temp[i] + idcount in L-BaseTree/main.c.

Rather than introduce a compile-time switch, this function picks the representation that produces a consistent (suboffset + sublen) ≤ length(ids) layout. The check is cheap (one pass over sublen) and robust as long as the catalogue isn't truly malformed.

GadgetIO.merger_trees_from_descendants — Method
merger_trees_from_descendants(keys, snaps, masses, desc_keys;
                              no_descendant = -1, particle_mass = 1.0,
                              positions = nothing, mostbound = nothing) -> Vector{MergerTree}

Build a forest of MergerTrees from a flat descendant table — e.g. the particle-ID re-link produced by link_by_shared_ids (relink_rockstar.jl), or any external catalogue. Each node i has a unique keys[i], a snaps[i] (snapshot number → SnapNum), a masses[i] (→ M_TopHat, and Len = masses/particle_mass so the most massive progenitor heads each chain), and desc_keys[i] = the key of its descendant (or no_descendant if it is a root).

Optionally pass positions (a vector of 3-tuples/vectors, → Pos) and mostbound (a vector of ids, → MostBoundID) per node so the resulting trees carry positions (e.g. for 3D trajectories) and a back-reference to the source catalogue.

Nodes are grouped into connected trees by following the descendant chain to its root; within each tree the pointers are made local (0-based) and FirstProgenitor/NextProgenitor are filled by set_progenitor_pointers!, so the result plots directly with MakieHelper.plot_merger_forest.

trees = merger_trees_from_descendants(keys, snaps, mvir, desc_keys;
                                      no_descendant = (-1, -1), particle_mass = 3.87e7)
plot_merger_forest(trees; snap_to_scale = s -> a_of[s], mass_of = h -> log10(h.M_TopHat))

GadgetIO.parse_ct_header — Method
parse_ct_header(line) -> Dict{String,Int}

Parse a consistent-trees column header line of the form

#scale(0) id(1) desc_scale(2) desc_id(3) num_prog(4) ... Tidal_ID(36) Rs_Klypin(37) ...

into a map of (lower-cased) column name → 0-based column index. Each token looks like name(idx); the parenthesised index is authoritative (so the map is robust even if tokens are reordered). Tokens without an explicit (idx) are assigned their running position as a fallback.

Punctuation that only decorates a name in the header but never appears in the lookup keys we query (?, /, |, [, ], ...) is preserved in the returned keys verbatim; query through ct_col, which lower-cases and tries a couple of spellings.

GadgetIO.read_block — Method
read_block(filename::String, block_id::Union{String, Integer};
            parttype::Integer=0,
            block_position::Integer=-1,
            info::Union{Nothing,InfoLine}=nothing,
            h::Union{Nothing,SnapshotHeader}=nothing,
            offset=0, n_to_read=-1)

Reads a block in a snapshot with block_id as a given name or position in the file. Defaults to reading gas particles. Block Names are case sensitive.

Keyword Arguments

  • parttype: Which particle type to read (0-indexed)
    • 0: Gas (default)
    • 1: Dark Matter
    • 2: Boundary
    • 3: Bulge
    • 4: Stars
    • 5: Black Holes
    • -1: All particle types
  • block_position: Position of the block in the data file [bytes]. Can be used to speed up IO.
  • info: InfoLine for the given block. Can be used to speed up IO, or if no INFO block is present.
  • h: SnapshotHeader for given file. Can be used to speed up IO.
  • offset: Adds an offset to start reading the block at a later point. Can be used for sub-IO.
  • n_to_read: How many particles to read. Can be used for sub-IO.

Examples (Format 2)

In case an INFO block is present:

gas_pos = read_block(filename, "POS", parttype=0)

If not you need to supply your own InfoLine

pos_info = InfoLine("POS", Float32, 1, [1, 1, 1, 1, 1, 1])
gas_pos = read_block(filename, "POS", info=pos_info, parttype=0)

# Examples (Format 1)
In case you want to read the default blocks:

julia gaspos = readblock(filename, 1, parttype=0)

If not you need to supply your own `InfoLine`

julia posinfo = InfoLine("", Float32, 1, [1, 1, 1, 1, 1, 1]) gaspos = readblock(filename, 1, info=posinfo, parttype=0) ```

GadgetIO.read_consistent_trees — Method
read_consistent_trees(filename; particle_mass=CT_DEFAULT_PARTICLE_MASS)
    -> Vector{MergerTree}

Read a single consistent-trees tree_*.dat file and return one MergerTree per tree it contains, ready for analysis or for MakieHelper.plot_merger_tree.

The column layout is taken from the #scale(0) id(1) ... header line (see parse_ct_header), so a non-vir MASS_DEFINITION or extra trailing parameters are handled automatically. particle_mass (in Msun/h) sets the conversion Len = round(Mvir / particle_mass) so that MakieHelper's default mass_of = h -> log10(Len) is sensible; for science plots prefer passing an explicit mass accessor, e.g. mass_of = h -> log10(h.M_Crit200).

Example

using GadgetIO, MakieHelper, CairoMakie

trees = read_consistent_trees("rockstar_run/trees/tree_0_0_0.dat")
@show length(trees)

# real scale factors for the x-axis (see scale_factor_map)
scaledict = scale_factor_map("rockstar_run/trees/tree_0_0_0.dat")

fig, ax = plot_merger_tree(trees[1];
                           mass_of = h -> log10(h.M_Crit200),
                           snap_to_scale = s -> scaledict[s])

                       particle_mass=CT_DEFAULT_PARTICLE_MASS) -> MergerTree

Read only the single merger tree whose root halo (the present-day halo, the one with desc_id == -1) has the largest mass_field, without building a MergerTree for every other tree in the file.

read_consistent_trees materialises one MergerTree per tree in the file (>10^5 for a full box, ~1 GB). When you only want the assembly history of the most massive halo, this streams the file once, keeps just the rows of the current best candidate, and converts that single tree at the end — a small fraction of the time and memory.

"Most massive" is judged by the root halo's mass_field (default "Mvir", i.e. the present-day virial mass), matched case-insensitively against the file's column header (so "m200c", "m200b", ... also work). consistent-trees emits each tree's root first, so only the root rows are parsed during the scan.

Example

using GadgetIO, MakieHelper, CairoMakie
tf   = "rockstar_run/trees/tree_0_0_0.dat"
tree = read_most_massive_tree(tf)
amap = scale_factor_map(tf)
fig, ax = plot_merger_tree(tree; mass_of = h -> log10(h.M_Crit200),
                                 snap_to_scale = s -> amap[s])

To instead pick the most massive halo across a whole trees/ directory, take the argmax of read_most_massive_tree over the tree_*.dat files.

GadgetIO.scale_factor_map — Method
scale_factor_map(filename) -> Dict{Int,Float64}

Build a Snap_idx → scale map from a consistent-trees tree_*.dat file by reading the scale (column 0) and Snap_idx (column 31) values of every data row. consistent-trees stores a real scale factor per halo, so this lets you put the merger-tree plot on a physical scale-factor axis instead of MakieHelper's (snap+1)/(last_snap+1) heuristic.

Pass the result to plot_merger_tree via the snap_to_scale keyword:

scaledict = scale_factor_map("rockstar_run/trees/tree_0_0_0.dat")
plot_merger_tree(trees[1];
                 snap_to_scale = s -> scaledict[s],
                 mass_of       = h -> log10(h.M_Crit200))

If a snapshot index appears with (slightly) differing scale factors across halos, the last one read wins; in practice all halos of a given snapshot share the same scale.

GadgetIO.set_progenitor_pointers! — Method
set_progenitor_pointers!(links::LinkTable)

Build the FirstProgenitor/NextProgenitor linked lists from the already-filled Descendant field. Mirrors L-HaloTrees' set_progenitor_pointers: at each descendant, progenitors are inserted into a linked list so that the largest halo (by Len) sits at FirstProgenitor. Within the chain, ordering matches the C code so that downstream consumers (galaxybox-style traversals) see the same sequence.

Operates on the SoA LinkTable so each insertion is a single Int32 write rather than a 104-byte struct copy.

GadgetIO.shrinking_sphere_center — Method
shrinking_sphere_center(pos; shrink=0.9, fmin=0.1, nmin=20) -> Vector{Float64}

Iterative shrinking-sphere centre of the 3×N position matrix pos (columns = particles). Starts at the centre of mass and repeatedly keeps the particles within shrink×(current maximum radius) of the running centre, until fewer than max(nmin, fmin*N) particles remain (or the set stops shrinking). Robust to the tagged cloud being partially stripped or captured.

GadgetIO.track_id_groups — Method
track_id_groups(snap_bases, groups; parttype=1, verbose=false,
                shrink=0.9, fmin=0.1, nmin=20) -> Vector{Dict{Int,NamedTuple}}

Follow many Lagrangian sets at once. groups is a vector of particle-ID vectors (e.g. the output of tag_innermost_ids). For each snapshot the union of all IDs is read once with read_particles_by_id, the tagged particles are bucketed back to their groups, and every group's shrinking-sphere centre is computed from that read — so the cost is one read per snapshot, not one per group. Returns one snapnum => (center, nfound, rms) map per group. Groups are assumed ~disjoint (a shared ID is attributed to the last group listing it).

pos0/r0/use_keys are forwarded to read_particles_by_id; pass a search centre+radius and use_keys=true to use Peano-Hilbert keys for fast region reads when a .key index exists (otherwise the whole ID block is scanned, which still works).

track_ids(snap_bases, ids; parttype=1, verbose=false, shrink=0.9, fmin=0.1, nmin=20,
          pos0=nothing, r0=0.0, use_keys=false) -> Dict{Int,NamedTuple}

Follow a single Lagrangian set of particle ids (type parttype) across the snapshots in snap_bases (a snapnum => snap_base map). For each snapshot reads those IDs' positions and returns (center, nfound, rms): the shrinking-sphere centre, the number of IDs located, and the rms distance to the centre (a size / stripping proxy).
